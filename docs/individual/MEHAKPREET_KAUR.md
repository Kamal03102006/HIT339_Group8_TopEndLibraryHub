## Personal reflection

Working on the TopEndLibraryHub project was a valuable learning experience that allowed me to develop my technical knowledge, problem-solving skills and confidence in software development. My main responsibilities were developing the Self-Service Kiosk and Secure Read-Only Catalogue API. These components required me to work with the existing ASP.NET Core MVC application, SQL Server database, Entity Framework Core, authentication system and GitHub repository.

At the beginning of the project, one of my biggest challenges was understanding how the existing application was structured and how my assigned components would interact with the work completed by other team members. Rather than developing a completely separate application, I needed to ensure that my kiosk and API could operate within the shared library management system. This helped me understand the importance of reviewing existing code, following project requirements and considering integration from the beginning.

My first major contribution was developing the self-service kiosk interface. I worked on creating a user-friendly layout that allowed library patrons to search the catalogue, filter items by category and availability, and enter library codes to identify items. I focused on making the interface simple and accessible because kiosk users should be able to complete basic library activities without needing extensive technical knowledge. Developing these features improved my understanding of Razor views, MVC controllers and the relationship between front-end interfaces and database records.

The most challenging part of my contribution was implementing the checkout functionality. Initially, although the kiosk interface and item scanning worked, checkout did not complete successfully. Through testing and troubleshooting, I identified that the authenticated user account needed to be securely linked to a library borrower record. I worked on integrating the IdentityUserId relationship so that the system could identify the correct library membership without relying only on matching email addresses. After resolving this issue using a dedicated test membership, I successfully demonstrated the checkout of Discovering the Top End (BK-0001), including a 14-day borrowing period and a due date of 28 October 2026. Seeing this loan subsequently displayed in the correct patron's account was one of the most satisfying moments of the project because it confirmed that several separate components were communicating successfully.

Another important responsibility was developing the secure catalogue API. I worked on read-only access to library catalogue information and API-key authentication. During testing, I confirmed that a request without an API key was rejected with an appropriate error message. This helped me appreciate the importance of protecting application endpoints, validating requests and distinguishing public interfaces from secured application services.

Database integration was another significant learning experience. I worked with Entity Framework Core models, relationships, migrations and SQL Server records. I also needed to consider borrowing restrictions involving item availability, active loans, holds, branches and transfers. These requirements helped me understand that a successful checkout must involve more than changing an item's status; it must respect the rules of the wider library system.

I experienced several technical difficulties during development, including compilation errors, migration inconsistencies, merge conflicts and problems launching the application through HTTPS. Resolving these issues required patience, careful investigation and repeated rebuilding and testing. In particular, Git conflicts involving ApplicationDbContext.cs, Item.cs, Program.cs and the Entity Framework model snapshot taught me how easily shared files can be affected when several developers work on the same project. I learned the importance of preserving existing functionality, checking duplicate properties and reviewing merged code rather than automatically accepting one version.

Collaboration also played an important role in my development. My kiosk depended on other team members' work involving holds, notifications, branches and transfers. This encouraged me to communicate about shared borrowing rules and understand the responsibilities of different modules. I managed my changes through a dedicated Git feature branch, committed and pushed my work, and created Pull Request #8. Successfully merging my contribution into the group's main branch was an important achievement because it demonstrated practical experience with collaborative version control.

Testing was essential throughout the project. I tested the kiosk welcome page, catalogue searching, item scanning, successful checkout, patron account information, logout and API-key restrictions. I also prepared screenshot evidence to support my contribution. Alongside the technical implementation, I produced an API testing report, kiosk integration documentation, user-feedback documentation and a patron user guide. Preparing these documents helped me understand that software development involves not only writing functional code but also communicating how the system operates and how it should be maintained and used.

If I were to complete a similar project again, I would establish shared database conventions and integration requirements earlier, coordinate changes to common files more closely, and test merged functionality more frequently. I would also maintain a more detailed development log from the beginning so that my time spent coding, debugging, testing and documenting could be recorded accurately. These improvements would help reduce integration problems and make collaboration more efficient.

Overall, this project strengthened my practical skills in ASP.NET Core MVC, C#, Entity Framework Core, SQL Server, authentication, API development, testing and GitHub collaboration. More importantly, it taught me how to approach unfamiliar technical challenges systematically, take responsibility for my assigned work and persist when a solution does not work initially. I am proud of completing my kiosk and API contribution and successfully integrating it into the group repository. The experience has increased my confidence in contributing to larger software development projects and highlighted the importance of teamwork, testing, security and continuous learning.
